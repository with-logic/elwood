## 12. End-To-End Testing

The repository should provide `npm run test:e2e` as a separate, opt-in quality
gate for slow and potentially paid real-agent testing. The e2e suite MUST run
the public TypeScript library API against real local CLI processes and real
PTYs, minimizing mocks and seams. It should verify the critical library flows
for each installed/authenticated supported adapter: start, terminal output,
raw input, prompt/message submission, hook observation, activity observation,
resize, stop, resume when the adapter reports a resume id, kill/teardown, and
Elwood-owned state cleanup.

`test:e2e` may skip an adapter when its CLI is not installed or cannot pass a
basic version/authentication preflight, but it should not use fake PTYs, fake
hook bridges, or fake agent processes for the adapter flows it does run. Because
the suite depends on local auth, network, model availability, and user-installed
CLIs, it is intentionally separate from `npm run check`. E2E coverage should be
reported separately and made as high as practical; unit/conformance tests remain
responsible for hard-to-force error paths and 100% default coverage.

Neither gate may write the developer's own Codex home or read its state; the e2e
suite only copies its `auth.json`. By default, every `test:e2e` process runs with
`CODEX_HOME` pointed at a private directory seeded with only a 0600 copy of that file,
removed when the process exits. A single e2e file run on its own gets the same default.
A test that needs its own Codex config uses another private home, seeded the same way,
for its duration. Whichever private home is active receives the project trust entries,
model selections, sessions, and logs Codex persists while the suite drives it, so none
of them reach the developer's config. The default gate runs each test file with `HOME`
and `CODEX_HOME` pointed at a private directory. Both gates refuse to create these
homes when the temp directory is inside the developer's Codex home.

The e2e suite may not write the developer's own Claude config either. By default,
every `test:e2e` process, and a single e2e file run on its own, runs Claude with
`CLAUDE_CONFIG_DIR` pointed at a private directory, removed when the process exits.
It is seeded with three copies: a 0600 `.credentials.json` holding the developer's
Claude login without its refresh token, so the copy can never rotate and so
invalidate the developer's own login; the developer's global config without its
per-project entries or MCP servers; and Claude's cached model catalog. The global-config
entry Claude writes for each scratch project, its transcripts, and its history land
there, never in the developer's `~/.claude.json` or `~/.claude/`, which are only read.
The private directory holds none of the developer's settings, so the suite runs Claude
with Claude's defaults rather than the developer's permission mode, hooks, or plugins.

The repository should also provide `npm run check:all`, an opt-in convenience
gate that runs the default `npm run check` gate and then `npm run test:e2e`.
`check:all` does not change the composition of `npm run check`; the default gate
remains free of real-agent dependencies.
