## 5.12 Dashboard statistics

The live `activity` stream carries optional `tokenUsage`, `rateLimits`, and
`subagent` observations on their existing transcript and hook result events.
Read these fields with the session's status and lifecycle events. All values
come from native JSONL or validated hooks. Missing evidence leaves the field
absent. The transcript reader's existing bounds, cadence, and resume baseline
apply. No additional polling, account request, or terminal input is needed.

- A Codex `event_msg` with `payload.type: "token_count"` supplies
  `tokenUsage` with `scope: "thread"`, cumulative `total` counts, and optional
  `last` request counts and `contextWindowTokens`. Replace the previous snapshot
  for that transcript path. A cumulative snapshot on a resumed thread can
  include prior usage. Use the reported total and treat cache and reasoning
  counts as components of the native accounting.
- A committed, non-synthetic Claude assistant record with a native message ID
  and valid input and output counters supplies `tokenUsage` with
  `scope: "response"`, `responseId`, and `counts`. Input counts include reported
  cache reads and cache writes. Show `cacheReadInputTokens` and
  `cacheWriteInputTokens` as components of input. The first activity from the
  record carries the observation. If no readable activity was produced, emit
  `kind: "other"` with label `token_usage` and no raw transcript record. This
  event still carries any valid speed observation (§5.11). Claude may update
  the same message across records. Upsert by transcript path and response ID
  before summing `counts.totalTokens`.
- A Codex `token_count` can independently carry `rateLimits` with its optional
  native `limitId` and one or both `primary` and `secondary` windows. Each
  window reports `usedPercent`, `remainingPercent` (clamped at zero), and any
  reported `windowMinutes` and `resetsAtUnixSeconds`. A valid native record
  timestamp is exposed as `recordedAt`. The timestamp records the transcript write. A later record from another
  session can repeat an older account balance. Keep these observations scoped
  to their session. Use an on-demand account read for cross-session balances. Only a new quota snapshot replaces the previous one. It may be
  absent or stale when idle.
  Claude quota availability is unknown on this surface.
- A `SubagentStart` hook result supplies `subagent: { id, type, state: "started" }`
  on both adapters. A `SubagentStop` result with no Elwood block decision supplies
  state `"stopped"`. Blank IDs and results after shutdown begins omit `subagent`.
  Track a set of observed IDs per live session to count active
  subagents, and discard the set on terminal exit. Repeated edges are idempotent
  by ID. Hooks are best effort and may miss native activity, especially for
  subagents already running when attaching or resuming. Other native hooks can
  also override stop decisions. Use session status to display the main agent.

Token counts must be nonnegative safe integers. Response IDs must be nonblank.
A malformed required counter
invalidates that count group. An invalid optional counter or quota window is
omitted. Percentages must be finite and nonnegative. The normalized observations
contain counters and native IDs only. The enclosing `activity.raw` follows the
existing activity privacy contract.

The activity types restrict usage and quota to the corresponding adapter's
transcript events with a transcript path, and subagent observations to hook
results. Codex projects stats before delivering the raw transcript event to
listeners. Raw transcript delivery still precedes activity delivery.

### Account quota before a session starts

`readAccountUsage(accounts?)` returns a promise for an ordered array of
`AccountUsage` readings. By default it checks the current Claude and Codex
sign-ins in that order, labeled `Claude` and `Codex`. An explicit list replaces these defaults. Each `UsageAccount` has an
`agent`, a nonblank `label` unique within that agent, and an optional absolute
`configDir` for that CLI's signed-in profile. An invalid profile list rejects with a `TypeError` before any
probe. Labels are caller-assigned. Each profile is checked independently through its native sign-in. A missing
directory or a login shell that replaces the selected profile yields an
unavailable result for that profile.

Each result carries the agent, label, ISO `checkedAt` time, status
(`available` or `unavailable`), and `windows`. Each reported percentage
window has a label, `usedPercent`, `remainingPercent` floored at zero, and
an optional ISO `resetsAt`. Known durations are exposed as `windowMinutes`
so hosts can align windows without parsing labels. `checkedAt` records when
the read finished. Preserve reported five-hour, weekly, and scoped
windows individually. Never infer a missing window or turn token counts into
account quota. Unavailable readings have an empty list. One unavailable account
does not hide another account's windows.

Each call requests the current account limits through the native CLI. It needs
no running Elwood session and sends no model prompt. Hosts can select either
percentage field for all accounts. Raw provider responses and credentials stay
out of the result. The library stores no account readings.
