# 5.14 Reading the screen as text

`ClaudeSessionApi`, `CodexSessionApi` and `ElwoodAgentSession` expose
`readScreen(options?: ReadScreenOptions): Promise<ElwoodScreen>`. It returns
what the session's terminal shows now, as rows of text, so that a host does
not have to replay raw `terminal:data` bytes through its own emulator.
`ClaudeSession` and `CodexSession` do not forward the call: after start, use
the raw session from their `session` accessor (§5.8).

```ts
type ReadScreenOptions = {
  /** `true` for every retained row, or the largest number of rows to return. */
  readonly scrollback?: boolean | number;
};

type ElwoodScreen = {
  readonly cols: number;
  readonly rows: number;
  /** The live screen: exactly `rows` entries, top to bottom, right-trimmed. */
  readonly lines: readonly string[];
  /** Rows above the live screen, oldest first. Empty unless requested. */
  readonly scrollback: readonly string[];
  readonly cursor: { readonly x: number; readonly y: number; readonly visible: boolean };
  readonly buffer: "normal" | "alternate";
  /** True once Elwood failed to draw output it received: the text may be missing some. */
  readonly outputLost: boolean;
};
```

### The live screen

The call waits for the terminal to settle, as `terminal.settled()` does, and
then reads. The result therefore includes all PTY output that Elwood had
received when the call was made. The wait also covers output that arrives
while it is pending, and it has no timeout: the promise resolves at the next
pause in output, or rejects when the session's terminal is disposed. It does
not wait for the CLI to finish what it is drawing, so a read during a repaint
can return a partly drawn frame. A host that must skip such frames can check
`terminal.xterm.modes.synchronizedOutputMode`, which is set while a CLI that
brackets its repaints is partway through one.

`lines` always holds the live screen: the bottom `rows` rows of the active
buffer, where the CLI draws. A host that has scrolled the terminal back still
receives the live rows. The call never moves the host's selected viewport and
never writes to the PTY. Each row is one terminal row with trailing blank
cells removed. A row that the terminal soft-wrapped is returned as separate
rows, with no flag to mark the continuation.

`cols` and `rows` are the emulator's size for that frame. `buffer` is
`"alternate"` while the CLI has switched to the alternate screen, and
`"normal"` otherwise.

`cursor.x` and `cursor.y` are zero-based cell coordinates on the live screen.
`cursor.y` is an index into `lines`. `cursor.x` counts terminal columns, and
it is not an index into the row's string: a wide character fills two columns
but one or two string units. `cursor.x` equals `cols` while the cursor waits
past the last column. `cursor.visible` is false while the CLI has hidden the
terminal cursor (DECTCEM). Both CLIs may hide it and draw their own.

`outputLost` is true once `terminal.renderFailed` is true (§5.3). The text
may then be missing output, and no later read can prove otherwise. `false`
does not mean the screen holds everything the CLI printed: rows the CLI
scrolled off the alternate screen, rows past the scrollback limit, and a
repaint in progress are all outside what it reports.

### After the session ends

`readScreen()` does not check the session status. After the CLI exits, and
while `stop()`, `kill()` or `teardown()` runs, it keeps reading the emulator,
so it returns the screen that the CLI left. That lasts until runtime cleanup
disposes the terminal (§9.4). A disposed emulator can no longer vouch for its
rows, so from then on `readScreen()` rejects with `session_not_running`. This
includes a read that was waiting when the terminal was disposed, and a host's
own `terminal.dispose()`. Once `stop()`, `kill()` or `teardown()` resolves,
the terminal has been disposed.

### Scrollback

Scrollback is best effort. By default `scrollback` is an empty array.
`scrollback: true` returns every row that the emulator still holds above the
live screen in the active buffer, oldest first. A number returns at most that
many rows, taking those nearest the live screen. `false` and `0` return
none. A number that is not a non-negative integer rejects with a `TypeError`
before anything is read.

The emulator's own limit also bounds the result. It is xterm's `scrollback`
option, 1,000 rows by default, and older rows are gone. The alternate screen
has no scrollback, so the array is empty while `buffer` is `"alternate"`.
Scrollback rows are terminal rows as they were drawn. A CLI that redraws its
own history can leave repeated or partial frames there.

### Privacy

Screen text can contain anything the CLI displayed, including account and
workspace details. Elwood reads it from memory on request. It is never
persisted (§2) and never written to `elwood` CLI output (§12A).

### Choosing between `readScreen()` and `terminal.snapshot()`

Use `readScreen()` to learn what the session shows. Use `terminal.snapshot()`
(§5.3) only to mirror the viewport that the host selected on the terminal
handle. The snapshot is synchronous and follows the host's scroll position.
It returns only the `rows` rows of that viewport, with no separate scrollback
list, and reports its cursor row relative to the live screen even when it
shows other rows.
