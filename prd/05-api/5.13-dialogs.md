# 5.13 Native dialog discovery

Eager and lazy Claude and Codex sessions expose
`listDialogs(): Promise<readonly ElwoodDialogRequest<Agent>[]>`, with `Agent`
equal to `"claude"` or `"codex"` for their respective sessions. The public
`ElwoodDialogRequest` type defaults to `"codex"`. Calling the lazy method
starts the session if needed. The list contains a complete native workspace
trust request while it blocks startup for a human decision. Automatic trust
policies still control their own prompts until raw caller input takes over
or the current automation attempt expires.

A request has readonly `id`, `elwoodSessionId`, `agent: "claude" | "codex"`, `kind: "trust"`,
`label: "workspace_trust"`, `targetPath`, `targetScope: "folder" | "repository"`,
`text`, and `choices` in native display order. Each choice contains an opaque
`id` and the native `label`. The `text` contains the native question and
explanation with whitespace folded. Use `targetPath` and `targetScope` for
the exact trust target. Redraws, unsettled repaints and cursor movement retain
the request and choice IDs during one continuous appearance. A settled frame
that no longer shows the menu ends that appearance.

Discovery requires a complete layout in settled native PTY output and an
independently verified launch folder or repository root. Elwood captures the
scope before spawning the CLI and revalidates it for the read. Each optional
evidence lookup allows up to 500 ms. A timed-out recheck ends discovery if its
native frame is still current. If another frame has superseded it, the newer
frame can be checked. If two expired filesystem checks are still waiting for
the OS, a new check requires a poll after one finishes. Unavailable evidence,
ambiguous paths and unsupported
layouts leave the existing native hold in effect. For Claude, losing
verification of the launch path or Git scope retires discovery for that launch.
Claude can wrap the path across rows in a narrow terminal. Discovery accepts
it only when the native wrap margins are intact and the rows reconstruct the
exact checked launch path. For a numbered Claude menu, the two options must
be numbered 1 and 2 in display order, with one marked selection.
Host output injected via
`terminal.writeOutput()` or direct xterm writes, host clears and resets, and
a size change after PTY output begins revoke native discovery
evidence for the life of that terminal. Scrollback selection does not affect
discovery. Positive native composer clearance or session closure ends the
startup discovery window.

The method returns the verified request or an empty array. A repaint with
unsettled output or an outstanding proof for an older frame can temporarily
return an empty list. The method does not flush pending terminal output. Use
the native terminal to respond. Ordinary
prompt submissions stay held until the native gate clears.
