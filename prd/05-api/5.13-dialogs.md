# 5.13 Native dialog discovery

Eager and lazy Claude and Codex sessions expose
`listDialogs(): Promise<readonly ElwoodDialogRequest<Agent>[]>`, with `Agent`
equal to `"claude"` or `"codex"` for their respective sessions. The public
`ElwoodDialogRequest` type defaults to `"codex"`. Calling the lazy method
starts the session if needed. The list contains a complete native workspace
trust request while it blocks startup for a human decision. Automatic trust
policies still control their own prompts until raw caller input takes over
or the current automation attempt expires. An active Codex `dialog` listener
can receive a newly human-owned prompt without another redraw.

A request has readonly `id`, `elwoodSessionId`, `agent: "claude" | "codex"`, `kind: "trust"`,
`label: "workspace_trust"`, `targetPath`, `targetScope: "folder" | "repository"`,
`text`, and `choices` in native display order. Each choice contains an opaque
`id` and the native `label`. The `text` contains the native question and
explanation with whitespace folded. Use `targetPath` and `targetScope` for
the exact trust target. Redraws, unsettled repaints and cursor movement retain
the request and choice IDs during one continuous appearance. A settled frame
that no longer shows the menu ends that appearance.

Discovery requires a complete layout in settled native PTY output and an
independently verified launch folder or repository root. Elwood captures the
scope before spawning the CLI and revalidates it for the read. Overlapping
list reads may share a pending check for the same frame. Each optional
evidence lookup allows up to 500 ms. A timed-out recheck ends discovery if its
native frame and lookup are still current. If another frame has superseded it, the newer
frame can be checked. If two expired filesystem checks are still waiting for
the OS, a new check requires a poll after one finishes. Unavailable evidence,
ambiguous paths and unsupported
layouts leave the existing native hold in effect. For Claude, losing
verification of the launch path or Git scope retires discovery for that launch.
Claude can wrap the path across rows in a narrow terminal. Discovery accepts
it only when the native wrap margins are intact and the rows reconstruct the
exact checked launch path. For a numbered Claude menu, the two options must
be numbered 1 and 2 in display order, with one marked selection.
Host output injected via
`terminal.writeOutput()` or direct xterm writes, host clears and resets, and
a size change after PTY output begins revoke native discovery
evidence for the life of that terminal. Scrollback selection does not affect
discovery. Positive native composer clearance or session closure ends the
startup discovery window.

Each list call checks that the verified frame is still current before returning
the request or an empty array. Unsettled output or an outstanding list proof for
an older frame can temporarily yield an empty list. Listing does not flush pending
terminal output. Codex listing does not wait for event delivery. Respond to
Codex through the native terminal. Claude also supports
[`answerDialog()`](5.3-claude-session-api.md) when automatic trust is disabled.
Ordinary prompt submissions stay held until the native gate clears.

## Codex dialog events

A `dialog` event has a request and `phase: "raised" | "closed"`. Elwood verifies
`raised` before dispatch. Listeners registered at dispatch start that are still
registered when called receive the same immutable snapshot. Changes made by a listener affect later reads and
deliveries. Buffered lazy listeners attach before the initial dispatch and share
its snapshot. A listener attached after an announcement receives a separately
verified `raised` replay of the still-current request after registration returns.
During a repaint, replay waits for settled
native output to verify the same request. Unsubscribing or retiring the request
cancels pending replay.

Retirement takes effect immediately. A subsequent `closed` event reports a
request previously raised by the session. A listener can receive `closed` even
if it did not receive that request’s `raised` event. Reasons are `"cleared"` for native composer clearance,
`"replaced"` for a different supported layout or target in settled native output,
or `"unavailable"` for lost evidence or session closure. A replacement gets
its own verification after `closed` dispatch before it can be raised. Listener
failures do not interrupt terminal processing.

Each `raised` dispatch and late replay requires an independent proof. Event
checks start only with a subscriber. Unsubscribing cancels the pending replay
or the last subscriber’s check. In-flight OS calls can finish later, and
publication coalesces checks while two publication lookups remain outstanding.
An ordinary redraw of an announced request needs no event check when no replay
is pending. See [§5.4](5.4-events.md) for diagnostics when a dialog listener fails.

## Claude dialog events

Eager and lazy Claude sessions emit a typed `dialog` event with the verified
request and `phase: "raised" | "closed"`. Closed events include a `reason`.
Use `cleared` for verified composer clearance, `replaced` for another supported
native trust menu, and `unavailable` if evidence is lost, a settled layout
cannot be verified, or the session closes.

Each announcement and retained replay verifies the exact current frame and
its scope with a fresh check. Event checks run while listeners are subscribed.
An unchanged announced menu needs another publication check when a replay is
pending. List and event reads collect separate proofs under the same limit of
two unfinished filesystem checks. If both slots are in use, publication
checks the latest frame when a slot opens. A list can return empty in that
case and the caller can poll again. If a dialog callback runs during a pending
list check, the list checks scope again.
A new listener receives a still-current active request after registration
returns. Replay waits through an unsettled repaint and resumes if the same
menu becomes current. Unsubscribing or retiring the request cancels replay. A
listener whose replay is canceled by retirement can receive `closed` alone.
A snapshot error during the first publication leaves independent list checks
available when the viewport becomes readable again. The native menu remains
available for input while optional discovery is unavailable. Listener failures
do not interrupt terminal processing. See [§5.4](5.4-events.md) for diagnostics.
